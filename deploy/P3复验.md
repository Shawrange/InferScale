# 原生 Linux 进程：P3 定向复验

此次包中三份策略日志仍为 `round_robin`。先上传本补丁的 `scripts/server_smoke.py` 覆盖服务器同名脚本；以下命令在项目根目录、Gateway 虚拟环境中执行。无需重启或重装 vLLM 两个副本。

## 1. 从正在使用的原生配置复制

以下假设 Gateway 原来用的是 `configs/server.yaml`；若启动时使用其他文件，应替换这里的路径。保留原生进程的 127.0.0.1:8100/8101 地址，不改成 Docker 服务名。

```bash
python - <<'PY'
from pathlib import Path
import yaml
source = yaml.safe_load(Path('configs/server.yaml').read_text())
for policy in ('least_load', 'cost', 'prefix'):
    config = dict(source)
    config['routing'] = dict(source.get('routing', {}), policy=policy)
    Path(f'configs/server-{policy}.yaml').write_text(
        yaml.safe_dump(config, sort_keys=False), encoding='utf-8')
PY
```

## 2. 每轮停止旧 Gateway，再启动指定配置

在旧 Gateway 所在终端按 Ctrl+C，确认退出；不要关闭两个 vLLM 后端。以 Least Load 为例，在该终端启动：

```bash
mkdir -p runs/p3-recheck
set -o pipefail
python -m inferscale.main --config configs/server-least_load.yaml --host 127.0.0.1 --port 8000 2>&1 | tee runs/p3-recheck/gateway-least_load.log
```

另开终端、激活 Gateway 环境，核对并执行：

```bash
curl -f http://127.0.0.1:8000/health/live
python scripts/server_smoke.py --expect-policy least_load --output runs/p3-recheck/gpu-least_load-smoke.json
```

live 中 policy 必须是 `least_load`，否则先检查启动使用的配置文件；仅修改报告文件名不会切策略。Cost / Prefix 重复以上步骤，分别把配置、日志和 `--expect-policy` 都替换成 `cost` / `prefix`。每轮 Gateway 日志的 routing_decision.policy 也须与目标一致。

## 3. 补 GPU 取消证据

现有日志已经证明网关记录了输出中的取消，不必重复只看 Gateway。下一轮需保留：

- 发请求前的两副本原始 `/metrics`，尤其 running/waiting 和按 finished_reason 分类的 counter。
- 请求参数（含实际 max_tokens）、客户端取消时刻、对应 Gateway request_id，以及取消前请求仍在执行的采样。
- 取消后的原始 `/metrics` 和可关联的后端 abort/终止日志。使用不会在取消前就自然结束的生成任务，不能把“最终空闲”单独作为通过依据。

若 abort counter 无变化，不先断言代码失败，也不标记通过；结合原始日志检查是不是自然结束、长度结束或指标记录方式不同。

最后打包 `runs/p3-recheck/` 与每轮配置，避免用 `*.json` 漏掉误命名为 `.json~` 的文件。此步骤是功能验证，不是性能比较。

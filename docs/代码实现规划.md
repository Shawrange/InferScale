# InferScale 秋招版代码实现规划

更新：2026-09-23。**P0–P3 已验收；P4 实验工具已实现，真实 GPU 实验与最终图表待完成。** 双 4090 的四策略协议与 usage 已核对，GPU 取消采用用户人工确认，不重复要求补证。见 [P3验收结论](validation/P3验收结论.md)。

当前 157 项 CPU 测试通过，含 B1–B6 和真实 socket 命令链。新增三种固定轨迹、open-loop/closed-loop runner、增量原始样本、request/attempt 关联、汇总与重复轮次比较；详情见 [P4实现与验收](P4实现与验收.md)。服务器采用原生 vLLM 进程，操作见 [P4实验运行](../deploy/P4实验运行.md)。

P2 历史版本另有 20 分钟 socket 混合运行结果，保留在 [P2验收](validation/P2验收.md)，不充当当前 P4 版本的长跑或 GPU 性能结果。

当前工作基线为本文及 `docs/核心正确性约定.md`。替代上一版 8 个里程碑、12 批交付的生产平台规划；根目录设计中的生产扩展章节保留作参考，不作为秋招版验收条件。

## 1. 项目目标与范围

做一个能演示、能复现实验、能解释权衡的多副本推理网关：**一个模型、两个同构独立 Replica、四种路由、三类实验**。Cost-Aware 纳入本轮核心范围，落实用户要求的公式修订。

| 必须完成 | 首版不要求 |
|---|---|
| 单进程 FastAPI Gateway，文本 chat 流式/非流式 | 多 Gateway、分布式状态、跨节点调度 |
| 静态两个 Worker，健康检查与陈旧状态过滤 | Kubernetes、自动发现、HPA、滚动发布 |
| RR、Least Load、Cost-Aware、Prefix-Aware | 异构 GPU 校准、复杂剩余耗时预测 |
| 并发上限、deadline、取消、响应提交前最多一次重试 | 多租户配额、RPM、动态反馈背压 |
| 成本/请求账本、基本 metrics、结构化决策日志 | 完整 Grafana/DCGM/分布式 tracing |
| Mixed、Shared Prefix、Hot Prefix 三类实验 | 六种 workload、完整权重 sweep、全套混沌平台 |
| 核心单测、socket 集成、Docker Compose、README/报告 | 大量框架抽象、复杂发布流水线 |

第一条 API 是 `POST /v1/chat/completions`（文本消息、n=1）。`POST /v1/completions` 作为共享控制器上的薄适配在 P2 补齐，只支持单个字符串 prompt。健康检查和 `/metrics` 保留。未知/不支持参数明确拒绝，不承诺完整 OpenAI API 兼容。

默认单信任域、自用实验环境，不声称多租户缓存安全。可配置一个环境变量 API Key；不公开部署为多租户服务。Prefix 用真实模板 token IDs 和模型身份构造稳定 fingerprint，保留 TTL/容量上限即可。

## 2. 四项修订与完成标准

详细算法、状态规则与用例见 `docs/核心正确性约定.md`，以下为实现追踪表。

| 问题 | 首版解决方式 | 落地阶段 | 验收 |
|---|---|---|---|
| 成本公式无效 | Worker 未完成成本 C + 当前请求成本，原子预占；明确同构池当前请求成本本身不改排序 | P1 账本及 P3 评分/预测已实现 | C1–C5 CPU 通过 |
| 请求计数泄漏 | request/attempt 双身份，字典作为唯一账本，统一幂等 finally 清理 | P1 本地回收与 P2 网络清理已实现 | L1–L6，GPU 取消另验 |
| 流式重试重复输出 | 预提交有界预取；commit_started 后禁止重试；旧前导数据丢弃 | P2 已实现 | S1–S6 |
| 实验口径失真 | 请求与 attempt 分表、完整失败分母、chunk/token 分开、固定到达与缓存条件 | P0 定数据格式，P4 完整落地 | B1–B6 |

不能用“规则写完”代替测试通过；以交付记录区分已验证的 CPU 行为、未完成的策略及 GPU 功能。

## 3. 精简代码结构

以下保留目标目录。proxy、SSE、API、telemetry、四策略、预测、Prefix、远端 tokenize 已实现；Compose 和服务器 smoke 已提供，完整 benchmark 留待 P4。准入收敛在 ledger/proxy 中，不额外创建 admission 抽象；fake Worker 实际位于 `src/inferscale/testing/worker.py`。

```text
pyproject.toml
uv.lock
src/inferscale/
  main.py                # app factory、启停
  config.py              # 配置与 ModelSpec
  models.py              # Request、Attempt、Reservation、Outcome
  api.py                 # 请求子集和错误映射
  admission.py           # 入站/全局并发；快拒绝
  lifecycle.py           # 请求所有权、终态、统一清理
  proxy.py               # HTTP、预取、retry、deadline、cancel
  sse.py                 # SSE 增量解析与终止识别
  registry.py            # 静态 Worker、健康、采样快照
  ledger.py              # 原子 select+reserve、幂等 release
  features.py            # tokenizer、输出预测、prefix TTL 表
  policies.py            # 四种同步策略，不做 I/O
  telemetry.py           # 核心 metrics 和 JSON 日志
benchmark/
  workloads.py           # 三类可重复数据
  runner.py              # closed/open-loop、原始样本
  report.py              # 汇总、分母校验、报告
tests/
  fakes/worker.py
  unit/
  integration/
  fixtures/
configs/local.yaml
configs/benchmark.yaml
deploy/compose.cpu.yaml
deploy/compose.gpu.yaml
docs/
README.md
```

技术选型：Python 3.12、FastAPI、Pydantic v2、httpx、pytest/pytest-asyncio，基础指标直接输出 Prometheus 文本格式。Gateway 不依赖 vLLM/PyTorch；vLLM 在独立容器或 Linux GPU 主机运行。Python 依赖已精确锁定；后端镜像验证后再锁定，不预填未经验证的版本组合。

一个 Uvicorn worker，内存状态，不引入 Redis。HTTP client 在应用启动时创建、关闭时统一回收；推理、采集与 tokenize 使用独立连接池。真实 tokenize 通过有界并发槽调用 vLLM 渲染接口；多一次 RTT 的开销必须在所有策略中保持一致。

## 5. 各阶段的最小约定

### P0：先让协议可模拟

fake Worker 暴露相同文本生成路径和 `/health`、`/metrics`。故障由测试配置控制，不放进 Gateway 对外 API：首输出延迟、role-only 后断开、首内容后断开、指定 502/503/504、每次输出间隔、合法空输出。提供可核验的 request/attempt 记录，用于证明“B 是否被调用”。

`ModelSpec` 先保存模型名、模板/tokenizer identity、上下文上限和输出默认值；CPU fixture 提供确定的 token 数。真实 tokenizer 在 P3 对齐，但输入长度校验与字段边界从 P2 就要有。

### P1：账本先于成本策略

`active_requests` 与 `reservations` 为唯一事实来源，Worker 数量/成本由此求和。同一把短锁内选择并预占；网络操作在锁外。释放用 ID 幂等删除，request owns attempts，重试只换 attempt。

Gateway queue=0，全局/每 Worker 达上限立即 503；每个策略共享相同门槛。远端指标单独存储，不覆盖或重复加入本地 reservation。无健康 Worker 时 readiness 失败，请求快速 503。

### P2：默认保守重试

仅响应提交前的连接失败/reset/提交前流异常截断/选定上游 502/503/504 可以跨 Worker 重试一次；关闭 transport 隐式 retry。response start 尝试前置 `commit_started`，提交后失败直接截断并记 partial failure。

所有路径回收上游和账本；close 超时先回收本地并隔离可疑 Worker。body、SSE 事件、前导缓存和非流式 JSON 均有大小上限；pool/connect/first-output/idle/overall/downstream-write/cleanup 有明确预算。有限并发既覆盖 tokenize 也覆盖正在流式传输的请求。

### P3：先有 baseline，再加两个增量

1. RR：共同候选门槛下轮转。
2. Least Load：`n_i / request_capacity_i`，同分轮转。
3. Cost-Aware：严格使用《核心正确性约定》§1 的公式，不额外混入 KV 权重造成归因不清。
4. Prefix-Aware：`score_cost - gamma * affinity`，affinity 在 [0,1]，成功完成才更新，TTL+条目上限，健康失败/实例变化失效；先过滤容量再打分。

冷启动没有可信成本状态时退回 RR。prefix 的 N、TTL 和 gamma 固定入 manifest；短于 N 的 prompt 不建立该 fingerprint。跨模型身份不共享 fingerprint，单信任域共享缓存，不包装多租户安全能力。

真实后端接入必须验证两个 API 的 stream/non-stream、模板 token 数、usage 与实际终止事件、关闭连接后的取消。若事件与假设不符，先修改 adapter/fixture 再做实验。

### P4：数据先于图表

保存 manifest、requests.jsonl、attempts.jsonl；report 先检查分母恒等式，再生成 TTFT/E2E P50/P95、成功吞吐、拒绝/错误率、Worker 分布。TPOT、token throughput 和真实 cache hit 只有数据可靠才报告。

open-loop 到达不受请求结束控制；本地发送器超限必须显式报告。区分测量窗口吞吐与 drain 后 cohort 完成情况。三类 workload 使用固定轨迹和缓存准备，至少 3 轮重复；不要求为每个策略证明正收益。

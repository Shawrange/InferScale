# P3 CPU 实现与服务器交接

更新：2026-09-23。P3 按秋招项目范围验收通过：四策略真实协议/usage 和路由日志已核对，缓存观测已接通；GPU 取消按用户人工确认通过。正式性能进入 P4，见 [P3验收结论](validation/P3验收结论.md)。以下保留 CPU 实现与原交接记录。

## 已实现

- `routing.policy`：`round_robin`、`least_load`、`cost`、`prefix`，每次进程启动固定策略；全部共用准入、健康/TTL、容量、重试和清理。
- Least Load 比较活动请求数 / Worker 容量；相同得分轮转。
- Cost 比较 `wq*n/capacity + wc*(C+cost_r)/cost_reference`。评分日志保留当前请求项，实际排序去掉该公共项，避免巨大数值让浮点精度抹平已有成本差异。选择与预占同锁原子执行，释放原 reservation。
- 输出预测按单模型的 prompt token 数 `bit_length()` 分桶。缺数据用模型默认输出量；EWMA 从该默认值起步，估计取 `min(cap, prediction)`。只有成功、stop/length、可信且与输入计数吻合的整数 usage 更新；取消/失败/缺失/不一致 usage 不更新。触顶样本保留计数与日志标记。
- Prefix 指纹为模型/tokenizer/template identity 与前 N 个实际 token IDs 的 SHA-256。短于 N 不建立；只有成功完成后写入，TTL 与全表条目数有上限。affinity 是 0/1 启发值，**不是实际 KV cache 命中率**。
- 健康失败、TTL 断档、drain、quarantine 和实例变化使旧 affinity 失效；旧 attempt 完成不能重建已失效代次的记录。容量过滤优先于亲和评分，gamma=0 与 Cost 决策一致。
- `tokenizer_mode: vllm` 通过健康后端 `/tokenize` 获取真实 token IDs；单独有界连接池/准入槽、响应体上限、超时和取消。失败明确返回错误，禁止回退字符数。没有新增 transformers/PyTorch 到 Gateway。

运行假设：同一模型两副本只接收该 Gateway 的推理，正式轮次从干净后端启动。`costs_known=False` 的底层选择接口会回退 RR 并记录原因；当前没有从远端负载重建成本的能力，不能在线接管未知的遗留负载并声称成本状态可信。

远端 tokenize 默认选第一个健康 Worker，有额外渲染 RTT 与该端点容量瓶颈；四策略必须使用相同 tokenize 设置。真实模型与模板身份由不可变 snapshot 提供，服务器 smoke 检查两个后端的样例 token IDs 相同且与生成 usage 一致；这不能替代模型文件版本固定。

## 验证

测试覆盖 C1–C5 的手算、公共成本项不改排序、即时预占、预测更新后的原金额释放、usage 校验；Prefix 的 gamma=0、热点容量、TTL/健康/epoch 失效和内存上限；远端 tokenize 槽位、取消和协议异常；四策略流式/非流式反馈；打包的服务器 smoke 通过本地真实 socket 执行。

最终 **139 项 pytest 全部通过**；工作区运行 58.19 秒，部署包解压后独立源码运行 58.66 秒。Ruff lint/格式和离线 uv.lock 检查通过；CPU/GPU 两份 Compose 经 `docker compose config --quiet` 解析通过，服务器配置生成器可生成合法配置。

归档检查逐文件核对 SHA-256、排除虚拟环境/实际 env 文件；解压回归显式检查导入路径属于解压目录，防止误用原工作区的 editable install。该检查复用本机锁定虚拟环境，不等同于 Linux 上重新安装依赖或构建 Docker 镜像。

P2 的 20 分钟数据是上一阶段源码的证据，不能当本轮 P3 新源码的长跑结果。本轮不以 fake Worker 吞吐宣称策略性能收益。
